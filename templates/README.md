# Templates

Page scaffolds for a new screen, imported from the **Pliant Design System** Claude Design project
(`8f7377b8`).

| Template | File | What it scaffolds |
|---|---|---|
| App shell | [`app-shell/AppShell.dc.html`](app-shell/AppShell.dc.html) | The frame: light nav rail with org header and expandable groups, top icon bar, breadcrumb + 32px title, header actions, toolbar, content area. |
| Data-table page | [`data-table-page/DataTablePage.dc.html`](data-table-page/DataTablePage.dc.html) | A list page: search + Filter + result count + Download toolbar, hairline table with merchant/category cells, status-above-amount and card thumbnails, plus the record details drawer. |
| Settings / form page | [`settings-page/SettingsPage.dc.html`](settings-page/SettingsPage.dc.html) | A settings page: underline tab row, section heading, and label-above-value fields with hairline underlines and pencil edit affordances. |

Each is a `.dc.html` canvas document — markup plus a `DCLogic` class supplying the nav tree, icons
and demo data. They compose real components off `window.PliantDesignSystem_8f7377` and read tokens
through `var(--*)`, so they double as worked examples of the house layout metrics (36px page gutters,
18px header top padding, the 22px/14px toolbar rhythm).

## What was and was not imported

- **`ds-base.js` — imported.** 14 lines, and the useful part: it shows exactly which stylesheets a
  page must load and in what order (`tokens/fonts` → `colors` → `typography` → `spacing` → `shape` →
  `shadows` → `base` → `styles.css`), then the bundle. One `base` constant to repoint. It is byte-identical
  in all three templates.
- **`support.js` — deliberately not imported.** A 70KB *generated* Claude Design canvas runtime
  (`GENERATED from dc-runtime/src/*.ts — do not edit`). It is app machinery, not Pliant design
  content, and would rot in this repo. The templates reference it in a `<script src>`; that tag is
  left as-is so the files stay byte-faithful to the source.
- **`.thumbnail` — not imported.** Per-template preview binaries generated by the app.

## They will not render here

Same caveat as `ui-kits/`: `ds-base.js` resolves `../..` to the repo root and expects `styles.css`,
`tokens/*.css` and `_ds_bundle.js` there. None were part of this import, and this repo's tokens use a
different naming scheme (`--pliant-*`, see `tokens/README.md`) from the `--primary-main` style these
templates read. Treat them as scaffolds to copy structure from, not as pages to open.

One path note: the templates load the brand mark from `../../assets/logo-icon.svg`. In this repo that
file is `assets/logos/pliantIconLogo.svg`.
